Fitting giants in a box

How the council packs huge models into a finite slice of GPU memory.

Picture a moving truck

When you click the Deep preset, you are asking three large LLMs to think at the same time. Together they weigh about 81 GB. Your GPU has roughly 100 GB total, but the council caps itself at 60 GB to stay safe.

Think of it like packing a moving truck. The truck has a fixed capacity. Your furniture comes in different sizes. If everything fits in one trip you go once. If not, you make multiple trips, and you let the engine cool between runs.

📦
The truck has a hard wall

Try to load more than fits and the GPU throws an OOM error. The whole run dies. That is why we plan trips before we load.

One trip or many?

Before anything else the council adds up the total VRAM the selected models need and compares it to the 60 GB ceiling. That single comparison decides everything.

CODE 
from config import MAX_CONCURRENT_VRAM_GB

# Calculate total VRAM needed for all models
total_vram = sum(get_model_vram(m) for m in models)

# Only use batching if total VRAM exceeds the limit
if total_vram <= MAX_CONCURRENT_VRAM_GB:
    # All models fit - run in parallel (single batch)
    batches = [models]
    execution_mode = "PARALLEL"
else:
    # Need to batch to avoid VRAM exhaustion
    batches = create_vram_batches(models)
    execution_mode = "BATCHED"

The packing algorithm, step by step

When the parallel branch is impossible, this function decides which model rides in which trip. It uses a textbook trick called bin-packing with a greedy twist: sort biggest first, then drop each model into the first trip that still has room.

CODE 
def create_vram_batches(models: list[str], max_vram: float = None) -> list[list[str]]:
    """
    Group models into batches that fit within VRAM limits.

    Strategy: Sort by VRAM descending, then greedily pack into batches.
    This ensures large models run alone if needed, while smaller models
    can run together.
    """
    if max_vram is None:
        max_vram = MAX_CONCURRENT_VRAM_GB

    if not models:
        return []

    # Sort by VRAM requirement descending (largest first)
    sorted_models = sorted(models, key=lambda m: get_model_vram(m), reverse=True)

    batches = []
    current_batch = []
    current_vram = 0.0

    for model in sorted_models:
        model_vram = get_model_vram(model)

        if current_vram + model_vram <= max_vram:
            # Fits in current batch
            current_batch.append(model)
            current_vram += model_vram
        else:
            # Start new batch
            if current_batch:
                batches.append(current_batch)
            current_batch = [model]
            current_vram = model_vram

    # Don't forget the last batch
    if current_batch:
        batches.append(current_batch)

    return batches
PLAIN ENGLISH

Define the packing function — it takes a list of models and an optional ceiling.

A comment explaining the strategy: sort big to small, then pack one by one.

If the caller did not pass a ceiling, use the global one from config.

If no models were picked, return an empty list and go home.

Sort the list so the heaviest model comes first — like loading the sofa before the lamp.

Start with empty trip lists: no batches yet, no current batch, zero weight loaded.

Walk the sorted list, one model at a time, and look at its weight.

If adding this model would still fit under the ceiling, drop it into the current trip.

Otherwise close out the current trip, file it away, and start a fresh trip with just this model.

After the loop, do not forget to file the last trip you were building.

Hand back the full list of trips, in order.

The safety net

Numbers in the model table are minimums. Real usage drifts higher as the conversation grows. Two guardrails keep us off the cliff: a 20% memory cushion on every estimate, and a small cooldown between trips so the GPU can actually free its memory.

CODE — SAFETY FACTOR 
# Safety factor applied to VRAM estimates (1.20 = 20% buffer)
# Accounts for VRAM fragmentation, KV cache growth, and estimation errors
VRAM_SAFETY_FACTOR: float = 1.20

def get_model_vram(model: str, with_safety_factor: bool = True) -> float:
    base_vram = MODEL_VRAM_GB.get(model, 10.0)  # Default 10GB if unknown
    if with_safety_factor:
        return base_vram * VRAM_SAFETY_FACTOR
    return base_vram
PLAIN ENGLISH

Define a single number — 1.20 — as the official safety cushion.

The comment names the three reasons it exists: memory fragmentation, growing KV cache, and plain estimation error.

Define a helper that looks up the raw VRAM number for a model.

If the model is not in the table, assume 10 GB as a safe default.

By default, multiply by the cushion before returning — so callers always see the padded number.

If a caller explicitly opts out, hand back the raw value.

🛡️

20% buffer

Every reported model size is multiplied by 1.20 before planning. A 40 GB sofa becomes a 48 GB sofa in our books. Covers KV cache growth and memory fragmentation.

⏱️

Cooldown between trips

After a batch finishes, wait 1 second plus 0.5 seconds for every 10 GB it used. A 48 GB batch buys a 3.4 second pause before the next models load.

📉

Hard ceiling

60 GB on a 100 GB GPU — we never even try to use all of it. The unused 40 GB is the headroom that keeps OOM crashes rare.

⚙️
Safety factors are everywhere

Engineers pad every estimated number. Aircraft cables: rated 2× max load. Bridges: 3×. AI memory budgets: 1.2×. If a number in production code is exact, that is usually a smell.
