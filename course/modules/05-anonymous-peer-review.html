Anonymous peer review and consensus

How three models grade each other behind a curtain — and how that grade becomes a number you can trust.

The blind grant review

Imagine three scientists each submit a research proposal. The reviewers see all three — but the names have been stripped off. They are anonymized as Proposal A, B, and C.

Each reviewer grades the other proposals on three things. Then a panel chair looks at how aligned the reviewers were. Tight agreement means strong consensus; scattered scores mean the topic is genuinely contested.

!

WITH names (biased)

Reviewers see who wrote each proposal. They might favor a famous lab, a familiar style, or worse — their own answer. The score reflects the source, not the substance.

A

WITHOUT names (fair)

Reviewers see Proposal A, B, C. With no way to recognize a friend or a rival, they have to judge the content itself. This is exactly what scientific journals do — they call it double-blind review.

After Stage 1 finishes, each model has written its answer. Then something strange happens — every model gets to read everyone else's answers, but with the names stripped off, and is asked to grade them. The math on those grades becomes the consensus score you see at the top of the final answer.

Hiding the names

Here is the function that turns "Llama said X, Qwen said Y, Gemma said Z" into the curtain-up version: "Response A, Response B, Response C." It also drops the reviewer's own answer so nobody can grade themselves.

CODE 
def _anonymize_responses(responses: dict[str, ModelResponse], exclude_model: str) -> tuple[str, dict[str, str]]:
    """
    Create anonymized response text for peer review.

    Returns:
        Tuple of (formatted_text, mapping) where mapping is {"A": model_name, ...}
    """
    # Filter out the reviewer's own response
    other_responses = {k: v for k, v in responses.items() if k != exclude_model}

    # Create mapping: letter -> model name
    mapping = {}
    formatted_parts = []

    for i, (model, response) in enumerate(other_responses.items()):
        letter = chr(65 + i)  # A, B, C, ...
        mapping[letter] = model
        formatted_parts.append(f"=== RESPONSE {letter} ===\n{response.content}\n")

    return "\n".join(formatted_parts), mapping

What we ask the reviewer to do

The curtain is up. Now we send the reviewer a prompt that explains the job: score every other response on three criteria, on a 1-10 scale, in a strict format we can parse later.

i
Why the prompt is so strict about format

Asking the LLM to output in exactly Accuracy=X, Insight=X, Completeness=X format makes the response parseable. Free-text praise is useless to a regex. This is a basic but critical prompt engineering pattern: when you want structured output from an LLM, tell it exactly what shape you want.

Turning scores into a 0-100 consensus score

For each thing the reviewers scored, collect all the scores given. Measure how spread out they are. Average the spread across everything. Then flip the number so low spread becomes a high consensus value.

CODE 
# Calculate variance for each response on each criterion
variances = []
disagreement_details = []

# Get all response letters that were reviewed
all_letters = set()
for reviewer_scores in all_scores.values():
    all_letters.update(reviewer_scores.keys())

for letter in sorted(all_letters):
    for criterion in ["accuracy", "insight", "completeness"]:
        # Collect scores from all reviewers for this response+criterion
        criterion_scores = []
        for reviewer, reviewer_scores in all_scores.items():
            if letter in reviewer_scores and criterion in reviewer_scores[letter]:
                criterion_scores.append(reviewer_scores[letter][criterion])

        if len(criterion_scores) >= 2:
            variance = statistics.variance(criterion_scores)
            variances.append(variance)

            # Track significant disagreements (variance > 4 means scores differ by ~2+ points)
            if variance > 4:
                disagreement_details.append(
                    f"{criterion.capitalize()} of {model_name} (variance: {variance:.1f})"
                )

# Average variance across all scores
avg_variance = statistics.mean(variances)

# Convert to 0-100 score (inverse: low variance = high score)
# Max reasonable variance is ~20 (scores ranging 1-10)
consensus_score = max(0, min(100, 100 - (avg_variance * 5)))
PLAIN ENGLISH

Set up two empty buckets — one to hold every spread number we calculate, one to hold human-readable notes about big disagreements.

Build a list of every response letter (A, B, C...) that any reviewer actually scored.

Loop through each response letter in alphabetical order — we will visit A, then B, then C.

For every letter, walk through the three criteria one by one: accuracy, then insight, then completeness.

Gather all the scores reviewers gave for this specific letter-and-criterion combo into one small list.

Only continue if at least two reviewers actually scored it — you need two numbers to measure disagreement.

Compute the variance — the formal statistics measure of spread. Add it to our bucket.

If the variance is above 4 (scores differ by 2+ points), this is a real disagreement — log a human-readable note about it.

Once we have visited every letter and criterion, average all the spreads into one number — the typical disagreement level.

Flip it: low average spread should mean high consensus. Multiply the spread by 5, subtract from 100, and clamp between 0 and 100.

!
Variance is how engineers measure disagreement

It is the squared average distance from the mean (the average). Two reviewers giving 5 and 5 produce a variance of 0. Two reviewers giving 1 and 10 produce a variance of 40.5. Anytime you see a "confidence" or "agreement" number in software, there is a variance (or its cousin, standard deviation) under the hood.
