Meet the council

Six characters with six different brains — five locals and one cloud chairman.

The cast list

Think of the council like a medical tumor board. A surgeon, a radiologist, and a pathologist all look at the same case from different angles — none is "best," they are differently shaped.

When you check boxes in the UI labeled Llama, Qwen, Gemma, Mistral, those aren’t just names. Each is a different LLM with its own size, training origin, and personality.

L
Llama 3.3 70B — Meta’s flagship

Huge open source generalist with 70 billion parameters. Runs locally on your GPU. The heaviest hitter in the local lineup.

Q
Qwen 2.5 32B — Alibaba’s multilingual model

Strong middleweight from China. Especially good at non-English text. Runs locally.

G
Gemma 2 27B — Google’s efficient model

Punches above its weight for its size. Quick to load. Runs locally.

D
DeepSeek R1 32B — Reasoning specialist

Trained to "think out loud" through hard problems. Slower, but it shows its work. Runs locally.

M
Mistral 7B — Fast European model

The pocket-sized speed demon. Tiny brain, almost instant answers. Runs locally.

C
Claude Opus 4.5 — Chairman

The only non-local member. Made by Anthropic. Lives in the cloud and gets the final word. Reached via an API over the internet.

Local vs. remote — the most important distinction

The five local models live on the DGX machine itself. Claude lives in Anthropic’s datacenter. This single split shapes everything: cost, privacy, speed, and capability.

🏠

Local (via Ollama)

Runs on your hardware. Free per call. Private — the question never leaves the machine. Slower for big models because your GPU has to do all the work.

☁️

Remote (Anthropic API)

Runs in Anthropic’s datacenter. Costs money per call. The question travels over the internet. Smarter on average than any single local model — especially at long reasoning and synthesis.

🔑
The two-letter word that decides everything

If you see "inference" happening on your machine, it’s local. If it’s happening on someone else’s machine over the internet, it’s remote. That’s the whole concept.

Sizes you can feel

Each local model loads its model weights into VRAM on the GPU. Bigger model = more memory used. Think of VRAM like the trunk of a car — you only have so much space.

🚛

Llama 3.3 70B

~40 GB VRAM — basically the whole car. Best at: deep generalist reasoning when nothing smaller is good enough.

🚐

Qwen 2.5 32B

~20 GB VRAM — a roomy van. Best at: multilingual text and balanced answers.

🚐

DeepSeek R1 32B

~20 GB VRAM — same footprint as Qwen. Best at: showing its work on logic-heavy questions.

🚗

Gemma 2 27B

~17 GB VRAM — a hatchback. Best at: fast, broadly competent answers without needing a beast of a GPU.

🛵

Mistral 7B

~4 GB VRAM — fits in the glove compartment. Best at: speed. Can sit alongside anything else in memory.

☁️

Claude Opus 4.5

0 GB local VRAM — lives in the cloud. Best at: final synthesis, long reasoning, web search.

The roster, in code

Every model has a short ID (used to call it) and a friendly display name (used in the UI). They live together in config.py as a dictionary.

Gemma 2 27B from Google — fast for its size, broadly competent.

The presets — three named loadouts

Picking three models from a list of six is a small decision people make constantly. So the code ships three preset "loadouts" you can click to fill the boxes for you. Each one embodies a different kind of question.

CODE 
MODEL_PRESETS: dict[str, dict] = {
    "fast": {
        "name": "⚡ Fast",
        "description": "Quick answers with smaller models",
        "models": ["gemma2:27b", "mistral:7b"],
    },
    "balanced": {
        "name": "⚖️ Balanced",
        "description": "Good tradeoff of speed and depth",
        "models": ["qwen2.5:32b", "gemma2:27b", "mistral:7b"],

    "deep": {
        "name": "🔬 Deep",
        "description": "Thorough analysis with heavy hitters",

    },
}
PLAIN ENGLISH

Define three named loadouts the user can click. Each one is a small recipe.

First recipe: "fast." The decision baked in: don’t wait long, even if the answer is rougher.

Label shown on the button (with a lightning bolt so it reads as "quick").

Subtitle explaining the tradeoff in plain words.

The actual lineup: Gemma 27B plus Mistral 7B. Both small, both quick — a chat-speed council.

End of the fast recipe.

Second recipe: "balanced." The decision: I want decent depth without melting the GPU.

Label with a scales icon — this is the default sweet spot.

Subtitle describing the tradeoff.

The lineup: a mid-size model (Qwen 32B) plus the two fast ones. Three voices, still snappy.

End of the balanced recipe.

Third recipe: "deep." The decision: correctness matters more than speed today.

Label with a microscope — this is the "let it cook" mode.

Subtitle: thorough analysis, expect to wait.

The lineup: the biggest model on the roster (Llama 70B) plus a strong middleweight (Qwen 32B) plus the reasoning specialist (DeepSeek R1). Three different angles on hard questions.

End of the deep recipe.

Aha! moment

Knowing which model to pick is one of the most underrated skills in modern AI engineering. Almost every production AI app is really a router deciding which model gets which request. These three presets are that decision, frozen as code.
